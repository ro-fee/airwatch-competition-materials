# 图形能力盘点与迁移地图

> 文档性质：信号图形模块的真实能力清单、代码归属和渐进迁移计划。
> 本文不把“旧系统已有”写成“新工作台已全部接入”。
> 更新日期：2026-09-05

## 1. 先说结论

旧系统不是只有一种图，而是一套从原始信号到模型解释的观察工具：

- **时域波形**：信号随时间或采样点怎么上下变化？
- **频谱图**：能量集中在哪些频率？
- **时频图**：哪些频率在什么时间出现或移动？
- **瀑布图**：连续播放时，频谱随时间怎么变化？
- **星座图**：I/Q 点群的形状是否清晰？
- **特征图**：模型中间层提取到了什么模式？
- **特征分布图（t-SNE）**：不同样本的特征是否形成分组？
- **小波、双谱、J/R、HHT**：从不同角度观察局部变化、频率联动或统计特征。

新界面不应该把所有图同时塞到首页。推荐的展示层级是：

1. 主图区默认显示时域、频谱或时频图，占页面最大面积；
2. 右侧结果区显示识别结果、数据质量、模型版本和易懂的结论；
3. 主图区下方用紧凑的图形切换栏放时域、频谱、时频和瀑布；
4. 专家分析折叠区再放星座、特征图、t-SNE、小波、双谱、J/R、HHT；
5. 轴承故障频率图和无人机事件时间轴分别放到对应业务区域，不与历史射频图混淆。

`airwatch/ui/signal_workbench.py` 已接回正式 `main.py` 主页，不是 HTML 原型。复用已迁移的计算/绘图接口，不再增加算法副本。图形区占主体，右侧固定 250px 放解释与日志；下方一条波形/频谱/时频/动态瀑布切换，底部集中打开文件、采样率、窗长和刷新。瀑布设置仅该模式可见。小波、双谱、J/R、HHT 入口默认折叠，真实结果进入同一大画布，两槽仍交替保存（只在本次会话内）。

### 各层应该做什么

| 层 | 负责 | 不负责 |
|---|---|---|
| airwatch.analysis | 校验信号形状、区分实信号和 IQ、计算绘图所需数组 | Qt 控件、文件选择、模型加载、页面布局 |
| airwatch.ui.plots | 把已经准备好的数组画进 PlotWidget，统一颜色和坐标轴 | FFT/STFT 的业务判断、模型推理、训练 |

调用关系刻意保持为：

    旧页面或未来页面 → Qt renderer → analysis 变换

## 4. 新模块的输入约定

### 4.1 信号形状

prepare_signal() 只接受以下明确输入：

- 一维实数数组：普通实信号；
- 一维复数数组：复数 IQ；
- 2 × N 或 N × 2 的实数矩阵：两路 I/Q。

其他二维矩阵不会被偷偷拉平成一条线，避免把批量数据、特征矩阵或错误形状误画成看似正常的波形。

### 4.2 频谱和时频图

- 实信号频谱显示单边频率；
- IQ 频谱显示以 0 Hz 为中心的双边频率；
- 频谱和时频图必须显式给出正的采样率；
- 时频窗长不能大于信号长度；
- 默认时频重叠率明确为 50%，避免 SciPy 版本或打包环境改变时间片数量；
- 输入包含 NaN 或无穷值时拒绝计算，并把原因交给上层提示用户。

### 4.3 星座图

真实 IQ 才能直接画 I/Q 星座。普通实信号没有独立的 Q 路，因此默认拒绝；只有旧系统使用过的 Hilbert 解析信号兼容路径，才允许调用者显式选择。界面上应标成“解析信号兼容显示”，不能暗示它等同于真实 IQ 采集。

## 5. 迁移顺序和验收标准

按“一次只迁一类图”的方式推进：

1. 时域波形（本轮完成）：旧 plotsig 调用新变换和 renderer，旧页面仍可启动；
2. 频谱图（已完成）：恢复旧槽函数并接入 render_spectrum，补强频谱坐标、幅度、文件选择和错误路径验收；
3. 静态时频图（绘图迁移完成）：替换旧 STFT 绘图，统一窗长、坐标轴和颜色范围；
4. 瀑布图（本轮迁移完成）：复用播放、暂停、继续、停止，统一信号输入和帧计算；超长记录后台预计算待做；
5. 星座图（已迁移）：当前生成样本、类别和图形模式联动，真实 IQ 与 Hilbert 兼容显示明确区分；
6. 中间特征图和 t-SNE（迁移完成）：特征曲线/索引域谱及 t-SNE 后台任务已接入；旧 Grad-CAM/热力图分支不计入已验收能力；
7. 小波、双谱、J/R、HHT（绘图与统一后台会话完成）：HHT 已采用兼容当前环境的新后端；四类计算共享冻结请求、单任务/取消/旧结果保护，且只在 UI 线程渲染。真实采集数据与长时压力仍待验收；
8. 轴承故障频率图：在轴承技术验证区域单独实现；
9. 无人机事件时间轴：等真实无人机数据、标签、模型契约和评估证据齐全后再接入。

每次迁移都要满足：

- main.py 仍能启动；
- 不修改 main2.py；
- 不训练模型、不覆盖历史权重；
- 分析层不导入 Qt；
- 旧回归测试和新增单元测试通过；
- 输入错误能得到用户看得懂的提示；
- 不把演示数据、旧射频模型或轴承模型说成无人机结果。

## 7. 本轮明确没有做的事

### HHT 替代实现验收（2026-09-05，当前状态）

取舍原则：HHT 是辅助观察工具，不是轴承模型的运行依赖。不为它降低 NumPy/SciPy 或改动冻结模型。以下比较中只有选定方案完成实际数值试验；其他方案属于兼容性/工程成本评估，未做算法优劣跑分。

| 方案 | 考量与结论 |
|---|---|
| 修补 pyhht/tftb 或降级环境 | 旧 pyhht 引用已移除的 scipy.angle，tftb 要求 NumPy<2；全局补丁或降级会扩大影响面，不采用 |
| EMD-signal 1.10.0 + SciPy Hilbert | 已实测兼容现有环境，保留 EMD/HHT 分析思路；选定。与旧实现不保证数值相同 |
| emd 0.8.1 | 官方元数据显示还依赖 numba/sparse/pandas/dcor 等，功能丰富但依赖更重；本轮不安装、不声称数值优劣 |
| VMD（vmdpy 0.2） | 是不同的分解方法，需要模态数/惩罚参数；不应直接替换后仍称同一 HHT 实现 |
| EEMD / CEEMDAN | 增加噪声集成与计算成本，涉及随机性和可能的多进程；本轮不启用 |
| 继续用时频图/小波 | 现有可用的低风险观察方式，但不能冒称 HHT；可并存 |
