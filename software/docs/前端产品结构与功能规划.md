# 前端产品结构与功能规划

> 文档性质：前端改造施工图，不等同于功能已实现。
> 制定日期：2026-09-05

## 1. 总体定位

软件主线保持为“空域电波哨兵——面向低空无人机的端侧智能频谱感知与未知信号预警平台”。本轮先确定页面结构，再按小步、可回退的方式修改代码。

现有射频分析、GAN、轻量化和轴承诊断功能继续保留，但要区分产品角色：无人机功能是未来主业务；历史射频功能是已有专业分析；轴承、质量门和抗噪声实验是技术验证。轴承模型和历史射频模型都不能冒充无人机模型。

## 2. 四页信息架构

继续保留四个顶层页面，不立即增加第五页：

1. **频谱态势**：观察信号、频谱和动态变化。
2. **智能识别**：判断信号可能是什么，未来承载无人机识别主入口。
3. **鲁棒性实验室**：验证噪声、频偏、衰落、信号生成和轴承诊断流程。
4. **端侧部署评测**：验证模型在普通电脑和 Windows 安装包上的运行能力。

## 3. 功能状态

页面上的功能区必须明确标明状态：

| 状态 | 含义 | 当前例子 |
|---|---|---|
| 当前可用 | 当前代码、数据和模型能够真实运行 | 波形、频谱、瀑布图、五类历史射频识别、个体识别轻量化对比 |
| 技术验证 | 可以运行，但用于验证通用机制，不代表目标业务效果 | 轴承诊断、质量门、抗噪声实验、GAN 统计一致性 |
| 待接入 | 已预留位置，但真实模型或数据尚未完成 | 无人机检测、类型/状态识别、未知信号告警 |
| 缺少依赖 | 当前条件不足，不能给出结果 | 缺少权重、可选依赖或输入格式不匹配 |

无人机模型接入前只显示“待接入真实无人机数据与专用模型”，不得填入虚构概率、类别、告警数量或性能指标。

## 4. 频谱态势

### 当前可用

保留 NPY 文件导入、实信号/二维 IQ/复数 IQ、时域波形、频谱、静态时频图、动态瀑布图、小波、双谱、J/R、HHT，以及瀑布播放、暂停、继续、停止和重播。

### 未来预留

右侧预留频谱事件区域，字段包括活动频段、起止时间、持续时长、是否进入识别队列、风险等级和事件状态。检测模型未接入时保持空状态，不显示无人机事件结果。

## 5. 智能识别

### 顶部：三个业务分段切换（2026-09-05 已接入）

根据后续确认的融合工作台方案，智能识别顶部改为“无人机识别 / 通用信号识别 / 轴承检测”三个互斥入口，而不是把三个模块上下堆叠。当前落地范围见本节末尾验收记录；原第 6、11 节把轴承迁到实验室的安排已被这次明确确认的三业务入口方案替代。

### 无人机识别（开发版已知源已接入）

当前只接入 KU Leuven 开发冻结模型的三类已知源分类，输入、质量门、后台推理和结构化结果已形成闭环；未知拒识阈值、多任务类型/状态、风险等级和可追溯事件仍待接入。界面必须持续显示“未知拒识未评估”，不能把历史射频模型或轴承模型作为无人机结论。

### 中部：历史射频专业分析（当前可用）

保留信号个体、调制、通联、业务和编码五类识别，以及单文件、多文件/目录识别、多脉冲投票、中间特征和 t-SNE。它们可以复用未来需要的切片、投票、特征提取、按需加载和 CPU/CUDA 推理机制，但类别含义必须保持真实。

### 底部：专家分析

中间特征、特征图、t-SNE 和批量结果放入可折叠区域，普通用户先看主要结果，专业用户再展开细节。

### 三业务工作台本轮实现与边界

- `airwatch/ui/recognition_workbench.py` 重排现有 Qt 控件，由 `main.py` 在现有控件和轴承面板创建后连接；不改生成 UI 和 `main2.py`，不复制识别/训练算法。
- 顶部分段按钮带原创 QPainter 小图标（旋翼、信号条、轴承），使用深灰、青色和粉色细边；不是复制外部商标或依赖网络字体。按钮互斥切换页面；本轮未加滑动动画。
- 通用区输入信号、模型特征共用大画布，不再左右平分两张图；下方保留波形/频谱/时频、文件切换与两种画布入口。采样率、窗长、运行次数、特征类型和更新按钮折叠收纳。
- 底部操作条保留原任务、数据模式、文件和开始按钮。现有模型按任务自动匹配，未提供独立权重选择器；模型真正加载成功后，展示实际类名和权重文件名，任务更换后清掉旧模型提示。未将 AGENTS 中的历史模型表硬编码成当前加载事实。
- 右侧通用区读取结构化结果与操作日志，不解析文字拼造概率卡片。五类历史识别已统一接入带取消、过期结果保护和窗口预算的后台 Workflow；这不代表超长输入性能或业务准确率已验收。
- 轴承区复用现有冻结契约后台任务；文件/启动/取消/进度放底部，质量、结论、说明和专属日志放右侧（可滚动）。模型输出三种质量状态和拒绝规则不变。轴承计算不会因切换业务自动取消，完成结果留在轴承页；通用页日志不再混入轴承完成/取消/失败消息。
- 轴承图形已接入：真实 MAT 的驱动端振动波形和频谱预览在独立 QThread 运行，清单自动带出采样率和通道；结果区仍只显示冻结诊断结果。无人机页只显示待接入，识别按钮禁用，无概率、类别、事件或告警结果。
- 轴承图区现已接入 `airwatch/ui/bearing_plot_panel.py` 与 `airwatch/workflows/bearing_preview.py`：选择 MAT 后后台读取清单通道、预览波形；清单给出采样率时可切到频谱，清单外必须手填真实采样率。读取只使用 `normalization='none'`，不复用模型的 window_zscore；只显示前 65536 点，并标注总点数，不标注未经审计的故障频率。
- 轴承图预览与冻结推理解耦：预览失败不会清空或伪造诊断结果；选择/切换文件使用 token 和 QThread 的最新请求保护；取消/关闭会等待安全收尾。轴承后台诊断复用同一份清单通道选择逻辑，不在 UI 线程加载 MAT。
- 轴承模块收尾验收：专用环境下真实主窗口流程“加载 Normal_0.mat → 后台诊断 → 右侧展示 → 关闭”通过；图预览成功、诊断状态为“已完成/质量通过”、进度显示完整窗口数，关闭后无残留窗口。独立 CPU worker 对 Normal_0、B007_0、IR007_0、OR007@6_0 四个真实 CWRU 样本均返回结构化结果；其中 IR007_0 为质量提醒，其余三个为质量通过。该验收是功能闭环验证，不是准确率报告。
- 轴承取消验收：使用可控后台 worker 验证“运行中 → 发出取消 → 已取消”，不保留部分诊断结果。启动入口 `scripts/run_app.ps1` 已固定使用项目专用环境 `E:\CondaEnvs\rofee-bearing\python.exe`，避免双击启动时静默落到系统/base Python。
- 离开通用区使待完成 t-SNE 结果失效，已有通用数据与已完成结果仍保留在本模块。切换模块不会加载模型/训练或覆盖权重。共享状态栏仍可显示后台任务提示，但正文结果分区保存。
- 轴承图标题明确：原文件幅度（单位未核验）、频谱为当前预览段 FFT 幅值且非校准功率；它不是时频图、包络谱、故障频率标注图，也不改变冻结模型输入。
- 轴承频谱现支持手动输入几何参数和转速后绘制 FTF/BPFO/BPFI/BSF 理论参考线。 控件默认折叠为“参考线参数 +”，展开后采用单行紧凑布局，避免挤占主频谱；小窗口也保持图形与参数区不重叠。参数默认留空，不使用未经核验的轴承型号预设；界面显示参数来源为“用户填写”，采样率来源沿用“已审计清单”或“用户填写”。更换文件、刷新、取消、报错、改参数或切换回波形都会清除旧标线；超出当前频带的频率明确列入未显示项。计算假设外圈固定、内圈旋转、稳态转速、无滑移，仅用于频率对照，不作故障判定。
- 真实闭环验收：用 `Normal_0.mat`、`IR007_0.mat`、`B007_0.mat`、`OR007@6_0.mat` 在专用 CPU 环境直接调用现有 `BearingInferenceWorker`。四个文件均成功返回窗口级质量统计、文件级质量状态、标签、置信度、窗口数和耗时；输出未写回数据文件、契约或权重。结果摘要保存于 `logs/real_bearing_closed_loop_summary.json`。
- 本轮观察到真实差异：Normal_0 为 accepted/normal，B007_0 为 accepted/ball，OR007@6_0 为 accepted/outer_race_6，IR007_0 为 caution/inner_race。`caution` 不是失败，界面会显示“质量提醒”并提示复核；不能从这四个样本外推模型准确率。
- 打包：新布局仅使用已有 Qt/绘图依赖，图标内存绘制，无新增资源路径、第三方素材、系统绝对路径或依赖；正式安装包与干净机器未验收。

验收：专用 `E:/CondaEnvs/rofee-bearing/python.exe` 下完整 discover **332 项全部通过**；普通 smoke、脚本 118 项图形/后台专项、30 项瀑布测试、含模型权重 smoke、compileall 均通过。专项包含在完整计数内，不重复累计。新增轴承预览 8 项并完成四个真实 CWRU 样本闭环；离屏检查 1440×920、1180×760 轴承波形/频谱和结果区。真实样本输出是功能验收，不是准确率报告。

## 6. 鲁棒性实验室

保留条件 GAN、15 类调制信号生成、类别和样本数量选择、样本切换与 I/Q 波形。当前生成入口已迁移为 `HistoricalGenerationWorkflow` 深 Module：Qt Adapter 只提交不可变请求并展示结构化结果，模型加载、受限分批推理、取消检查、批内描述性评分和原子写盘均隐藏在 Workflow Implementation 中。每次成功运行提交唯一的“历史生成会话”目录及 `generation-session.json`；失败或取消清理隐藏暂存目录，不覆盖旧结果。界面中的“批内信号统计偏离”按类别分别计算，只用于定位同批次异常样本，不是真实 FID，也不验证类别或模型质量。

规划加性噪声、频率偏移、幅值变化、衰落和可选多径的对比实验。实验结果必须来自真实产物，界面不编造指标。

轴承诊断的当前入口采用智能识别顶部的“轴承检测 / 技术验证”（替代早期放在实验室的安排），继续使用已冻结的模型契约、标签映射、归一化方式和质量门规则。结果区区分正常、内圈故障、外圈故障、滚动体故障、低质量拒绝、推理中、已取消和出错。实验室未来可以引用其真实抗噪声评估证据，但不重复创建一套诊断入口。

## 7. 端侧部署评测

当前保留个体识别原模型与轻量模型的历史对比入口，并已迁移为三层边界：`airwatch/data/historical_comparison.py` 是带 SHA-256、大小、输入契约和安全上限的 Data Interface；`airwatch/workflows/historical_model_comparison.py` 是同时驱动两个模型并原子发布 `comparison-result.json` 的深 Workflow Module；`airwatch/ui/historical_comparison_background.py` 是只负责线程生命周期、进度和取消的 Qt Adapter。页面不再扫描目录或把目录名当真值，也不与通用识别页共享 `data/label/filename/model` 状态。

当前清单明确属于 `software_demo`，因此只展示模型参数量、权重大小、逐文件投票输出和窗口输出一致率；一致率标注为“非准确率”。OA、宏平均精度、F1 和端侧时延在结构化结果与 Evidence 中均为空。取消或失败不提交部分 Evidence。其他四类历史任务不在页面中展示为可用，未来 `edge.student` 槽位仍保持预留，等待后续训练和冻结证据接入。

后续接入真实审计测试集后，再增加模型版本、输入规格、CPU P50/P95、吞吐、峰值内存、源码运行、无 GPU 运行、PyInstaller onedir 运行和模型完整性检查。所有数值必须来自自动生成的 JSON/CSV 结果，不能把本次 Workflow 总耗时解释为端侧时延。

## 8. 统一结果卡片和线程状态

射频、轴承和无人机结果统一展示：结果名称、结果值、置信度、数据质量、模型版本、处理耗时和结论说明。低质量时显示“拒绝判断”，同时给出原因和建议，不能只显示低置信度类别。

后台任务统一显示等待中、准备输入、推理中、已完成、已取消和出错，并提供进度、取消、异常回传和资源清理；后台线程不得直接修改控件。

## 9. 无人机接口预留

前端不直接理解模型内部网络，只接收结构化结果。未来输入包括原始信号或标准化切片、采样率、中心频率、数据来源、录制标识、时间信息和预处理版本；输出包括目标检测、类别、工作状态、已知/未知状态、置信度或开放集分数、风险等级、事件时间、模型版本、数据质量和处理耗时。

## 10. Windows 打包要求

模型、标签映射、归一化配置、质量门规则、模型契约、内置数据和静态资源是只读资源，通过统一运行时路径加载，不能依赖当前工作目录。诊断结果、生成信号、日志、缓存和用户配置写入 LOCALAPPDATA/AirWatch 或 AIRWATCH_DATA_DIR，不写入安装目录和 PyInstaller 临时目录。

首次打包优先验证 PyInstaller onedir，再评估 onefile。模型加载、数据转换、批量推理和报告导出不得阻塞 Qt 主线程。

## 10.1 通用信号识别后台化审计与收口（2026-09-05～2026-09-20）

首轮审计曾用合成信号记录旧同步按钮路径的风险；这些内容是迁移前历史，不代表当前 Implementation。2026-09-20 的审计脚本已改为直接穿过维护中的 Data / Inference / Workflow Interface，仍只验证流程与权重只读性，不评估准确率。

首轮发现并现已消除的风险：

- 权重加载与前向已离开 Qt 主线程；Data Interface 设有单文件字节数、窗口数和重复运行总预算。
- 父目录只作为导航提示，冻结快照的真实标签默认留空；文件名中的 `=10` 等文本不会被提升为 SNR 真值。
- 权重统一经运行时资源路径解析，源码目录和打包目录不依赖当前工作目录。
- 通用识别使用独立 `general_input` 快照，不再与主页或轻量化比较共享模型槽位。

当前后台边界覆盖单文件、多文件、批量目录和重复运行：`recognition_input.py` 固化有限数组快照，`general_models.py` 严格加载历史权重，`general_recognition.py` 返回结构化预测、特征、每文件窗口数和尾部舍弃点数，`recognition_background.py` 管理线程、进度、取消与过期 token。重复运行只用于观察，不自动转成准确率或稳定性指标；t-SNE 继续使用独立后台任务。旧 `load_data_legacy`、`cut_data`、同步 `recognition` 和 `load_recognition_model` 已从 `main.py` 删除，追溯实现只留在 `main2.py`。

## 11.1 无人机识别开发闭环（当前）

无人机页面已接入 KU Leuven 开发冻结模型的已知源识别。`airwatch/workflows/uav_contract.py` 固定输入信息、质量状态、识别状态、已知/未知字段、窗口数、开放集状态、契约身份和置信度约束；质量拒绝、未完成和非法置信度均不得发布类别结果。`airwatch/ui/uav_background.py` 提供独立 QThread Seam，实际入口使用 `LazyKULeuvenRecognitionBackend` 延迟加载模型并支持进度、取消、异常和过期结果保护。`airwatch/data/uav_input.py` 负责格式 Adapter，`airwatch/workflows/uav_intake.py` 将统一通道布局、完整记录质量报告、源文件身份和用户声明采样率组成只读“无人机已准备输入”。预览与推理共享这一快照，不再重复读取文件；图形仍只显示最多 65,536 点，但质量检查覆盖完整记录。预览成功、质量未拒绝且用户明确填写真实采样率后才启用识别，Workflow 再核对冻结契约要求的 100 MHz、2 通道和 32×4096 点。结果卡片的处理窗口数、契约 ID 和开放集状态来自实际结果；已知/未知仍显示“未评估（阈值尚未冻结）”。当前能力只适用于冻结契约登记的三类已知源开发流程，不代表无人机检测、多任务状态识别、未知信号告警或跨源泛化已经完成。
