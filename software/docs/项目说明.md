# 空域电波哨兵项目说明

## 1. 项目定位

项目原名“智能信号处理原型验证系统”，是一套面向无线电与射频信号分析的 PyQt5 桌面软件。系统已有信号加载、时频可视化、五类深度学习识别、条件 GAN 信号生成和模型轻量化对比能力。

参赛改造后的统一名称为：

> 空域电波哨兵——面向低空无人机的端侧智能频谱感知与未知信号预警平台

目标赛道为全球校园人工智能算法精英大赛“算法创新赛道—AI+软件创新”。改造重点不是简单更换界面文案，而是把原先分散的信号处理功能收敛为一个可解释、可复现、可离线演示的低空频谱感知闭环。

## 2. 涉及领域

- 无线电与射频信号处理：IQ 数据、时域/频域/时频分析、信号切片和频谱瀑布。
- 人工智能算法：一维卷积、ResNet、TCN、多任务学习、开放集识别和知识蒸馏。
- 低空安全与无人机感知：无人机信号检测、类型/状态识别、未知设备告警。
- 桌面软件工程：PyQt5、pyqtgraph、后台推理、报告导出和离线安装包。
- 实验工程与可信 AI：数据来源审计、无泄漏划分、基线对比、消融实验和失败案例分析。

## 3. 当前已有功能

### 3.1 主页

- 打开 `.npy` 信号文件。
- 展示时域波形、频谱、静态时频图和动态频谱瀑布图。
- 支持实信号、二维 IQ 和复数 IQ 数据。
- 提取小波、双谱、J/R 和 HHT 特征；HHT 依赖为可选项。
- 动态瀑布支持 FFT 点数、历史行数、播放速度、暂停、继续、停止和重播。

### 3.2 信号识别

系统当前保留五类历史识别任务：

| 任务 | 切片长度 | 模型 | 输入 | 类别数 |
|---|---:|---|---|---:|
| 信号个体识别 | 1024 | `ResNet18_TCN` | 2 通道 IQ | 15 |
| 信号调制识别 | 1024 | `ResNet18` | 2 通道 IQ | 15 |
| 信号通联识别 | 5000 | `ResNet18_` | 2 通道 IQ | 5 |
| 信号业务识别 | 2048 | `ResNet18` | 1 通道实信号 | 2 |
| 信号编码识别 | 512 | `CNN` | 1 通道实信号 | 6 |

支持单文件、多文件、目录批量识别、中间特征和 t-SNE 展示。输入解码、冻结快照、分窗、权重加载和推理统一经 Data/Inference/Workflow Interface，并由 Qt 后台 Adapter 执行；不再把父目录或文件名当作经验证真值。

竞赛方向的“无人机识别”子页已接入 KU Leuven 本机开发版 TCN，当前仅对 FrSky、Spektrum DX4e 和 DJI Mini 2 三个已知信号源做 32 窗口成员级分类。权重、标签、预处理、聚合规则和运行代码由开发运行契约的 SHA-256 绑定；推理在后台线程运行，界面提供进度、取消、错误回传与清理。未知拒识阈值尚未冻结，所以界面固定显示“未评估”，不会把低置信度解释为未知无人机。

### 3.3 信号生成

- 使用条件 GAN 生成 15 类调制信号。
- 支持类别、样本数量、保存根目录和样本切换；每类最多 10,000 个、单次总量最多 30,000 个样本。
- 生成任务在独立 Qt 后台线程执行，提供进度、取消和异常回传。每次成功运行写入带 `generation-session.json` 的唯一会话目录；所有类别完成前只存在隐藏暂存目录，取消或失败会清理暂存内容，不覆盖历史会话。
- 当前展示的是按条件类别分别计算的“批内信号统计偏离”，仅辅助定位同一批次的异常样本，不是真实 FID，也不验证类别正确性、真实性或模型质量。
- 扩充前后效果对比在缺少真实验证集和两组模型时会明确拒绝生成演示数字。

### 3.4 网络轻量化

- 当前只有“信号个体识别”具备可用的原模型与轻量模型权重。
- 当前页面通过带 SHA-256 的软件演示清单固定文件身份、输入规格和顺序，在独立 Qt 后台线程对同一批窗口运行历史 TCN 对照模型与历史 10 层轻量模型。
- 页面与 `comparison-result.json` 只展示两组预测、参数量、权重大小和窗口输出一致率；一致率只是模型输出相似程度，不是正确率。
- 演示数据没有经审计真值测试集，因此 OA、宏平均精度、F1 和端侧时延均不发布。未来真实轻量化评测必须接入独立数据清单、冻结协议和机器 Evidence。
- 其他四类历史任务缺少轻量权重，不在页面中伪装为可用；竞赛端侧学生模型继续使用独立预留槽位，等待后续冻结模型和评测证据。

## 4. 当前软件结构

- `main.py`：唯一维护中的主入口和主要业务逻辑。
- `newwindow_.py`：`main.py` 使用的手工维护 PlotWidget 界面。
- `waterfall_plotter.py`：动态频谱瀑布计算、状态和绘图控制。
- `ui_theme.py`：全局深色主题。
- `models/`：网络结构和现有权重。
- `data/`：演示与流程测试数据。
- `datasets/uav/dronerf/`：已验证的 DroneRF V1 只读源包、录制/划分清单和 2.4 GHz 上下半带训练窗口；不随软件安装包分发。
- `datasets/uav/vti_droneset/`：已验证 SHA-256、作者密码和内容元数据的 VTI_DroneSET V1 归档及审计；当前与冻结模型输入不兼容，尚未用于模型实验。
- `datasets/uav/ku_leuven_drone_rf/`：KU Leuven V1.0 来源、许可、成员哈希、固定窗口和已知/未知协议审计；原始数据不随软件分发。
- `airwatch/data/`：无人机来源审计、DroneRF/KU Leuven 标签与录制边界、分组划分、流式选窗、显式频带选择和落盘复核。
- `airwatch/models/`：无人机 CNN、ResNet18、TCN 基线，以及已预注册消融的 STFT 频域分支和时频自适应融合模型。
- `airwatch/inference/`：校验运行契约、资源哈希、标签和预处理兼容性，并封装 KU Leuven 已知源预测。
- `airwatch/workflows/` 与 `airwatch/ui/`：把结构化无人机识别契约连接到 Qt 后台任务和无人机页面。
- `training/`：配置驱动的无人机训练、固定测试评估和消融协议执行入口。
- `airwatch/evidence/`：对训练、测试、多随机种子和消融结果做数据身份与协议一致性校验，并生成 JSON/CSV 汇总。
- `tests/`：瀑布专项测试和应用/模型冒烟测试。
- `main2.py`：历史兼容入口；直接运行时转向 `main.py`，其内部旧实现不属于当前维护链路。

## 5. 当前可信边界

- `data/` 中的数据主要用于验证读取、切片、绘图、模型前向和界面流程，不是原模型训练集。
- 不能用仓库演示数据的识别结果声明真实业务准确率。
- DroneRF 数据准备链和 CNN、ResNet18、TCN 统一训练/评估工程已经可复现；三个模型各完成 3 个固定随机种子，当前仍是同源录制级基线，尚未通过跨来源验证。
- 第一轮时频双分支消融已按冻结协议完成。验证集在四个预注册变体中选择自适应融合，但其单种子测试录音级 Macro-F1 为 0.8996，低于同种子 TCN 基线的 0.9365，因此当前仍以 TCN 为类型识别基准，不宣称双分支已超越基线。
- 已完成冻结检查点的 `-20～20 dB` 受控加性噪声压力测试。这里的 dB 是归一化原窗口功率与新增 AWGN 功率之比，不是物理采集 SNR。当前双分支在 `5 dB` 和 `10 dB` 显著弱于 TCN，尚无“低 SNR 增益”证据。
- 已训练首个确定性噪声增强 TCN。它在验证集保持 clean 录音 Macro-F1 `0.9365`，并在 `0 dB` 从原 TCN 的 `0.1333` 提升到 `0.4046`；该候选尚未进行独立测试，不能作为最终性能声明。
- 已建立 TCN 冻结检查点的开放集已知样本校准链：类别原型只从训练集拟合，MSP、Energy 与余弦原型阈值只由 33 条验证录音确定，目标已知接受率为 95%。当前尚未引入独立未知数据，不能报告 AUROC、FPR95 或未知拒识率，也不能声称软件已经具备经验证的未知设备预警性能。
- VTI_DroneSET V1 已通过作者密码验证及本轮内容审计。原始元数据为 150 MS/s，与当前 100 MS/s IQ 协议不同，聚合矩阵和标签未建立等价适配，因此本轮不作为可用的第二测试源；结论和检查范围见 `datasets/uav/vti_droneset/content-audit-v2.json`。
- KU Leuven Drone RF Dataset V1.0 的官方元数据、许可和首个 1.44 GB 数据包已核验；51 个 MAT 成员均已在 ZIP 内完成变量结构和成员级 SHA-256 核验，并生成 1,632 行固定窗口计划。论文证据把 `SJRC pro RC` 定义为 unknown source，本项目因此将整个归档锁为外部未知类测试，禁止训练、调参或选阈值。官方资料尚未证明各 MAT 为独立采集会话，正式结果必须先按成员聚合。DroneRF 原论文说明 L/H 是 40 MS/s 时域实幅值的 2.4 GHz 下/上半带；训练接口现可显式选择下半带且本机一轮训练链已跑通。KU Leuven 是 100 MS/s 复数 I/Q，两源统一派生表示尚未冻结，当前仍不运行跨来源测试。
- 为降低跨采集设备域偏移的混淆，开放集主实验已预注册为 KU Leuven 内部同硬件协议：Frysky、Spektrum DX4e RC、DJI Mini 2 RC 为计划已知源，NineEagles、WlToys、Q205、SJRC Pro 为论文未知源。三个已知源共约 5.81 GB、193 个 MAT 已完成全成员审计并生成 6,176 个固定窗口。冻结划分已分配 115/24/24 个成员到训练/验证/测试，边界之间保留共 30 个 guard；物理会话独立性未获官方证明，不得宣称跨会话泛化。固定 IQ 预处理已用于本机训练/验证，known test 和 unknown 仍未物化、未读取。
- KU Leuven 的 32 窗口成员级均值 softmax 聚合与已知验证集 95% 接受率阈值规则已冻结。本机 RTX 4060 已完成 TCN/ResNet18 各 3 个固定种子的训练，六个最佳检查点的 24 成员验证 Macro-F1 均为 `1.0`；该小验证集的聚合指标已经饱和，因此不能将其作为参赛测试性能。机器生成的事后诊断显示，TCN 最佳检查点窗口级 Macro-F1 三种子均值为 `0.7750±0.0229`，ResNet18 为 `0.6632±0.0651`，仅支持把更小的 TCN 作为下一轮本机开发候选。
- KU Leuven V2 受控增强实验的 `-5 dB` 单模型均值从 `0.3738` 降至 `0.3253`，概率集成仍为 `0.1818`。V3 只改为“clean 守门 + 三次 `-5 dB` 最差表现优先”的检查点选择，使 `-5 dB` 均值提升到 `0.5854`，但最差种子/重复仍为 `0.1818`，因此按预注册标准失败。
- V4 保留 V3 选择规则，只把 AWGN 分支中 `-5 dB` 的抽样占比从 `1/6` 提高到 `1/2`（占全部训练抽样 `12.5%`）。在同一重复使用的开发验证协议上，`-5 dB` 三种子/三重复均值由 V3 的 `0.5854` 提高到 `0.8569`，最差值由 `0.1818` 提高到 `0.6308`；clean 保持 `1.0`，`0/5 dB` 均值和多径均未退化，五项预注册验收全部通过。这仍是合成扰动下的开发证据，不是物理 SNR 或独立泛化结论。
- 软件已通过新的哈希绑定契约接入 V4 `seed=20260910` TCN，该种子是在已重复使用的 40 个开发条件上事后选出的综合均值领先者，仅用于演示已知源分类链路。运行契约的开放集状态为 `not_evaluated`、阈值为空，known test 和 unknown 仍未读取。
- 旧 A800 V1 配置与 dry-run 进度保留。2026-10-03 已接收 Claude Code 执行的 A800 V2 结果，完整归档在 `artifacts/imports/a800-v2-20261003/`；具体完整性检查、运行验证及接入范围见 `docs/A800训练结果归档与接入说明.md`。服务器选型报告保留 A 组 TCN、固定部署种子 20260909；扩窗、多尺度和一致性方案未达到预注册改进门槛。归档包括冻结后的已知测试、未知源评估和失败记录，本机已加载冻结模型并完成真实验证录制 CPU 推理及主要指标复算。上述早期“尚未读取测试/未知源”描述属于历史开发阶段，不能用于描述本次回传状态。桌面当前仍使用 V4，A800 发布尚未接入 UI；未知拒识存在较高误接受率，不宣称通用无人机检测或可靠未知设备预警。
- 真实 FID 需要外部真实样本和固定特征提取器；当前按类别计算的批内信号统计偏离不能命名为 FID，也不能解释为生成质量。
- KU Leuven 无人机识别、五类历史识别、历史信号生成、历史双模型比较和 t-SNE 已通过各自的 Qt 后台 Adapter 执行。主页小波、双谱、J/R、HHT 已统一为单任务后台“专家分析会话”：启动前冻结类型、采样率和当前选区，数值计算在工作线程执行，QPixmap 渲染与双槽提交只在 UI 线程执行；取消、切换基础图、打开新文件或关闭窗口会使晚到结果失效。仍需补充真实长记录压力和目标机交互验收。
- Windows onedir 构建分为默认 Release 与显式 Dev：Release 清理分析缓存并执行包内模型/Workflow 自检；Dev 复用稳定的 PyInstaller Analysis 缓存，仍保留资源、哈希和禁止依赖校验，但不能作为交付证据。当前最终 Release 已完成资源闭包、9 个模型角色 CPU 自检与 15 秒无界面启动；仍需目标 Windows CPU 机器人工验收。
- 当前历史五任务与“低空无人机感知”主题并不完全一致；无人机专用模型已有同源基线、消融、受控加噪压力测试和验证集抗噪候选，但尚缺抗噪独立测试、开放集、跨来源与端侧部署证据。

## 6. 参赛改造目标

参赛版需要形成以下闭环：

1. 导入或回放真实公开无人机射频数据。
2. 展示频谱占用、动态瀑布、估计 SNR 和检测事件。
3. 输出无人机存在概率、类型、工作状态及已知/未知置信度。
4. 将连续结果合并为可追溯的预警事件。
5. 展示低 SNR、开放集和轻量部署的真实实验结果。
6. 在普通 CPU 电脑上完成离线安装、稳定演示和报告导出。

详细范围、算法主线和验收指标见[参赛改造方案](参赛改造方案.md)。
