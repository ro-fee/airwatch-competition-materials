## 当前状态

截至 2026 年 9 月 4 日，本项目已经完成 CWRU 轴承故障诊断首个 `BearingCNN` baseline 的训练、固定测试集评估、抗噪声模型冻结、16 文件批量验收，以及独立 Qt 后台推理接入。训练、评估和推理仍在独立后台代码中完成；桌面只消费冻结契约产生的结构化推理结果。

这一步的意义是：先把“数据怎么读、怎么切、怎么分、模型怎么训练、结果怎么保存和复核”跑通。后续再做模型对照和界面接入时，都可以基于同一份数据清单、同一套评估规则和可追溯文件继续推进。

- **界面：无影响。** 没有修改 `main.py`、`main2.py`、`newwindow_.py`、`MainWindowui.py` 或 `MainWindowui.ui`。

- **运行方式：独立。** `training/` 不导入 PyQt，当前功能不会改变现有软件启动方式。
- **结果性质：内部实验。** CWRU 是实验室公开数据，本次结果不能直接当作真实现场、未知设备、低信噪比或竞赛性能证明。

## 当前冻结契约：抗噪声模型

在进入界面接入前，已经把新抗噪声模型的四件关键事项冻结：模型权重、标签顺序、归一化方式和质量门 V2 规则。冻结的意思是：后续推理必须按这份契约执行；如果要改其中任何一项，必须创建新的契约版本，不能直接改旧文件。

新抗噪声 checkpoint：

```text

输入：1 通道、每窗口 1024 点
类别数：4
训练增强：AWGN，20/10/5/0 dB；干净窗口保留概率 0.2
```

固定标签顺序：

```text
0 = normal
1 = inner_race
2 = ball
3 = outer_race_6
```

固定归一化：每个 1024 点窗口单独计算 `(x - mean(x)) / std(x)`。质量门先检查原始信号，不能先归一化；通过 `accepted` 或 `caution` 后才进入模型。标准差小于等于 `0.001` 的近似常量窗口直接拒绝。

质量门 V2 的三种结果：

- `accepted`：质量通过，进入模型，输出诊断和置信度。
- `caution`：质量一般，仍进入模型，输出诊断和置信度，但明确提示“仅供参考”。
- `rejected`：质量不足，不进入模型，诊断和置信度都必须为空，提示重新采集。

阈值来自 validation，不使用 test 选阈值：

```text
near_constant_std         <= 0.001 触发拒绝
clipping_ratio            > 0.003  直接拒绝（当前警告阈值与拒绝阈值相同）
spectral_flatness         > 0.435  触发拒绝
spectral_flatness         > 0.105  标记 caution
```

```text

airwatch/analysis/bearing_quality.py
```

## 防止误覆盖的规则

本轮已补充训练和评估产物保护：

- 每次训练/评估都使用一个安全的 `run_name` 作为输出文件名的一部分。
- 默认 run name 来自配置中的 `experiment_name`。
- 运行名不能包含路径分隔符、空白或 Windows 保留文件名字符。
- 如果 checkpoint、训练记录、测试记录或预测 CSV 中任意一个已经存在，程序会在正式训练/评估前直接拒绝执行。
- 没有“覆盖已有文件”的开关；要做新实验，必须使用新的 `--run-name`。
- `--dry-run` 只检查配置、数据和模型接线，并报告计划输出，不写入文件，也不会因为目标已存在而报覆盖错误。

示例：

```powershell
# 只检查，不训练、不写文件
python -m training.train --dry-run

# 新训练必须使用新的名字
python -m training.train --run-name bearing_cnn_baseline_retry_20260902

# 用冻结权重重新生成一份新的评估记录，不能占用旧文件名
python -m training.evaluate `
  --checkpoint artifacts/checkpoints/bearing/bearing_cnn_baseline_best.pt `
  --run-name bearing_cnn_baseline_recheck_20260902
```

当前冻结 checkpoint 保留原样，后续新实验不会覆盖它。

## Qt 后台推理接入（2026-09-04）

已将冻结的抗噪声轴承诊断接入维护中的 `main.py`，但没有把训练代码带入界面，也没有替换历史五类识别入口。新增接入边界如下：

```text
airwatch/ui/bearing_background.py          QThread worker + GUI-thread controller
airwatch/ui/bearing_presentation.py        accepted/caution/rejected 展示规则
airwatch/workflows/bearing_progressive.py  批次进度和协作式取消
main.py                                    独立轴承诊断面板和信号连接
ui_theme.py                                状态、按钮和进度条样式
tests/test_bearing_background.py            后台任务、展示规则和界面边界回归
```

用户点击“开始后台诊断”后，worker 在独立 `QThread` 中完成冻结契约校验、模型加载、CWRU `.mat` 读取、质量门 V2 和批次推理；GUI 线程只接收进度和结构化结果，因此不会被模型计算同步卡住。当前取消是**协作式取消**：界面发出请求后，worker 在当前模型批次结束时安全退出，不使用强制杀线程，也不保留部分结果。关闭窗口时会先请求取消并等待线程安全结束；超时则拒绝关闭，避免资源处于不确定状态。

三种质量状态的界面语义固定为：

- `accepted`：显示“质量通过”、故障类别和平均置信度。
- `caution`：显示“质量提醒”、故障类别和平均置信度，并明确“仅供参考，建议复核或重新采集”。
- `rejected`：显示“已拒绝诊断”，故障类别与置信度分别显示“未输出”，只建议重新采集；不会展示模型对该窗口的伪造预测。

实际后台界面链路已用 `datasets/bearing/cwru/raw/ball/B007_3.mat` 验收：118 个窗口完成，状态为“质量通过”，结果为“滚动体故障”，进度显示 `118 / 118`。该数字是一次真实推理运行的日志，不是模型性能指标。

本次新增回归测试 `tests/test_bearing_background.py` 共 13 项，覆盖批次进度、全局窗口索引、三态汇总、取消、异常转发、线程安全等待、重复启动保护和主界面 rejected 展示边界。
