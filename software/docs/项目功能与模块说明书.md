# 空域电波哨兵项目功能与模块说明书

> 版本：截至 2026-09-06  
> 文档用途：给项目使用者、开发者和后续维护人员看的“人话版”说明。  
> 重要原则：本文严格区分“当前可用”“技术验证”“已预留但未接入”和“后续规划”，不把规划写成已实现。

## 1. 项目一句话介绍

“空域电波哨兵”是一套运行在 Windows 电脑上的离线信号分析软件。它可以把信号文件读进来，画出波形、频谱、时频图和瀑布图，并调用已有模型进行部分信号识别。项目正在向“面向低空无人机的端侧智能频谱感知与未知信号预警平台”演进。

目前软件的无人机页面和数据接口已经预留，DroneRF CNN、ResNet18、TCN 三个离线基线已经各完成 3 个随机种子的训练与固定测试，但**尚未完成跨来源验证和部署验收，也没有接入为用户输出无人机类别或告警结论**。现有通用信号识别、轴承诊断和历史图形功能不能被说成无人机模型。

## 2. 先看结论：现在软件能做什么

| 状态 | 含义 | 目前实例 |
|---|---|---|
| 当前可用 | 当前代码、模型或数据能够真实运行 | 信号加载、波形、频谱、静态时频图、动态瀑布图、五类历史信号识别、部分轻量化对比、GAN 生成、轴承后台诊断流程 |
| 技术验证 | 机制能运行，但不能直接代表目标业务性能 | 轴承质量门、抗噪声流程、信号统计一致性分数、无人机输入/预览/质量检查 |
| 已预留/待接入 | 页面和接口已准备，但缺真实模型或数据 | 无人机检测、无人机类型/状态识别、未知信号告警、事件预警 |
| 缺少依赖 | 条件不满足时会明确提示，不强行给结果 | HHT 可选依赖、缺少某类轻量权重、未确认格式的原始 `.dat` 文件 |

## 3. 软件整体页面

软件目前保留四个顶层页面，方便从“看信号”逐步走到“识别、实验和部署评测”。

### 3.1 频谱态势（主页）

主要用途是观察信号。用户可以打开 `.npy` 文件，查看信号随时间变化的样子，或观察频率能量分布。

### 3.2 智能识别

页面顶部有三个业务入口：

1. 无人机识别：未来主业务，目前只做安全占位，不冒充已有模型；
2. 通用信号识别：当前可用的历史五类射频识别；
3. 轴承检测：技术验证模块，使用已经冻结的模型契约和质量门规则。

### 3.3 鲁棒性实验室

用于观察噪声、频偏、衰落等因素对识别的影响，并保留信号生成和轴承抗噪声实验的承载位置。它更像“实验台”，不是普通用户每天必用的识别入口。

### 3.4 端侧部署评测

用于比较模型的准确性、速度、参数量和模型大小等部署相关信息。只有真实存在的模型、权重和评测文件才会显示数字；缺数据时会提示，不会用随机数补齐。

## 4. 主页：信号加载和图形展示

### 4.1 支持的输入形态

- `.npy` 一维实信号；
- 二维双通道信号；
- 一维复数 IQ 信号；
- 历史流程使用的 `.dat` 文件；
- 其他格式必须明确数据类型、通道数、排列方式和采样率，不能单靠文件名猜测。

### 4.2 已有图形

| 图形 | 它在看什么 | 对用户有什么用 |
|---|---|---|
| 时域波形 | 信号幅值随时间的变化 | 看有没有脉冲、突发、饱和或明显异常 |
| 频谱图 | 信号能量落在哪些频率 | 看占用了哪些频段、是否有主峰 |
| 静态时频图 | 频率能量随时间的变化 | 看跳频、突发和频率漂移 |
| 动态瀑布图 | 连续帧的频谱变化 | 像“频谱录像”，观察信号是否出现、消失或移动 |
| 小波特征 | 不同尺度下的局部变化 | 观察瞬态和多尺度结构，偏专家分析 |
| 双谱 | 非线性和相位耦合特征 | 辅助分析复杂信号结构，偏专家分析 |
| J/R 特征 | 特定统计结构 | 为历史分析和模型输入提供辅助特征 |
| HHT | 瞬时频率和非平稳变化 | 依赖额外库，缺少依赖时不影响软件启动 |

动态瀑布支持 FFT 点数、历史行数、播放速度、暂停、继续、停止和重播。实信号显示单边频谱，IQ/复数信号显示双边频谱；频率轴使用当前采样率，不再写死。

## 5. 智能识别：通用信号识别

这是当前真正可以调用历史模型的识别模块。它不是无人机模型，而是原系统保留下来的五类无线电信号任务。

| 任务 | 输入切片长度 | 模型 | 输入通道 | 类别数量 |
|---|---:|---|---:|---:|
| 信号个体识别 | 1024 | ResNet18_TCN | 2 通道 IQ | 15 |
| 信号调制识别 | 1024 | ResNet18 | 2 通道 IQ | 15 |
| 信号通联识别 | 5000 | ResNet18_ | 2 通道 IQ | 5 |
| 信号业务识别 | 2048 | ResNet18 | 1 通道实信号 | 2 |
| 信号编码识别 | 512 | CNN | 1 通道实信号 | 6 |

支持：

- 单文件识别；
- 多文件和目录批量识别；
- 多脉冲投票；
- 中间特征展示；
- t-SNE 展示；
- 按需加载模型；
- CUDA 可用时使用 CUDA，否则使用 CPU；
- 后台任务的进度、取消、异常提示和重复运行保护。

这里的“识别结果”只表示对应历史任务的类别。例如调制识别输出的是调制类别，不是“某型无人机”。

## 6. 智能识别：轴承检测

轴承模块是一个独立的技术验证功能。它用于验证：如何把冻结模型、统一标签、归一化方法和质量门规则接到一个后台推理流程里。

### 6.1 当前包含的内容

- 已冻结的模型契约；
- 冻结的标签映射；
- 冻结的归一化方式；
- 冻结的质量门规则；
- 后台线程推理；
- 进度和取消；
- 异常提示；
- 三种质量状态的显示规则；
- 单文件和多文件识别流程的基础承载。

### 6.2 三种质量状态，用直白的话解释

- **通过（accepted）**：输入信号的基础条件满足，可以继续给诊断结果；
- **需注意（caution）**：信号可能存在满幅饱和等风险，结果可以展示，但要提醒用户谨慎；
- **拒绝（rejected）**：信号为空、包含 NaN/Inf、过短或没有幅值变化等，不适合继续判断。

“质量拒绝”不是模型判断出了某一种故障，而是软件先判断“这份输入是否值得让模型继续看”。质量门也不是 SNR，也不是模型置信度。

## 7. 智能识别：无人机模块

无人机模块目前的主要价值是把未来正式模型接入的位置、输入格式、结果格式和安全边界先搭好。

当前已具备：

- 页面入口和主图区域；
- `.npy` 实信号、二维信号、复数 IQ 读取；
- `.dat` 显式参数读取；
- 波形、频谱、时频预览；
- 输入大小和采样率检查；
- 基础信号质量检查；
- 独立后台任务、进度、取消和异常回传；
- 结果契约对“未完成、质量拒绝、未知结果”的约束。

当前没有：

- 真实无人机训练权重；
- 无人机存在概率；
- 无人机类型或工作状态结论；
- 未知设备识别效果；
- 可用于比赛的无人机准确率、F1 或开放集指标。

因此页面显示“待接入真实无人机数据与专用模型”是有意为之，不是功能坏了。

## 8. 信号生成和鲁棒性实验

### 8.1 条件 GAN

现有 GAN 可以生成 15 类调制信号，并支持类别、样本数量、保存目录和样本切换。当前界面中的分数是信号统计内部一致性分数，不能叫真实 FID，也不能据此声称生成数据提升了业务准确率。

### 8.2 抗噪声方向

项目已经建立统一输入幅值/量纲和低质量信号拒绝机制的技术路线。后续还需要在真实数据和固定评估协议下，比较不同噪声等级、频偏、衰落和开放集方法的实际指标。

## 9. 网络轻量化和端侧部署

当前只有“信号个体识别”具备可用的历史 TCN 对照模型和 10 层轻量模型。页面通过 SHA-256 软件演示清单在后台对同一批窗口运行两个模型，只展示参数量、权重大小、逐文件预测和窗口输出一致率。演示清单不提供经审计真值，因此不发布 OA、宏平均精度、F1 或端侧时延；一致率也不是准确率。其他任务缺少轻量权重，不在页面中伪装为可用。

端侧评测最终应该关注：

- 模型准确性和 Macro-F1；
- P50/P95 推理时延；
- 吞吐；
- 参数量和模型文件大小；
- 峰值内存；
- 普通 CPU 和 Windows 安装包能否稳定运行。

## 10. 后台任务和软件不卡顿

耗时工作逐步放到 `QThread` 或线程池中，界面线程只负责接收进度和显示结果。典型流程是：

1. 用户选择文件并点击开始；
2. 软件保存本次输入快照，避免用户中途改选择影响任务；
3. 后台线程加载数据、预处理和推理；
4. 界面显示阶段和进度；
5. 用户可取消；
6. 任务完成、失败或取消后清理线程；
7. 过期任务不能覆盖新任务结果。

训练代码不进入界面层，界面只消费已经冻结的模型和结果契约。

## 11. 数据和模型放在哪里

- `models/`：现有历史模型结构和权重；
- `models/legacy_weights/`：未维护的历史权重归档；
- `data/`：历史演示和流程测试数据；
- `result/`：生成信号和图形结果；
- `airwatch/`：新功能的数据、分析、推理、工作流和界面模块；
- `training/`：未来统一训练和评估入口；
- `tests/`：自动化测试；
- `docs/`：项目说明、方案、数据审计和技术文档。

目前登记的仓库本地演示数据为 30 个文件，包含 `.dat`、`.npy` 和 `.mat` 清单类型。这些数据用于读取、绘图、切片、前向和界面流程测试，不代表真实业务数据。

DroneRF V1 已从官方 Mendeley Data 下载并通过官方 SHA-256 校验，CC BY 4.0 许可已核实；23 个源包、227 条录制对、固定录制级划分和 7,264 个双频段窗口均已自动审计。CNN、ResNet18、TCN 在相同协议下各完成 3 个随机种子；TCN 的固定测试录制级准确率均值为 91.92%、宏 F1 均值为 93.14%（样本标准差 5.05%），CNN 宏 F1 均值为 91.89%（标准差 1.58%）。这是 33 条同源测试录制上的初步结果，不是跨会话或跨设备结论。

## 12. Windows 打包运行

项目已经加入统一资源路径和 PyInstaller `onedir` 打包方案，正式包输出位置为：

```text
dist/AirWatch/AirWatch.exe
```

项目图标为 `assets/airwatch.ico`。打包时模型和只读资源应随包分发，运行结果、日志和缓存写入用户可写目录，不写安装目录。

注意：开发机上的 PyTorch CUDA 打包已经做过 DLL 诊断，诊断版能够正常导入 Torch，但最终仍应在用户电脑上重新双击最新构建的 `AirWatch.exe` 做验收。不能仅凭源码运行就宣称安装包完成。

## 13. 用户实际操作建议

1. 用专用环境运行：`E:\CondaEnvs\rofee-bearing\python.exe`；
2. 打开主页，选择一个示例 `.npy`；
3. 先看波形和频谱，再尝试时频图或瀑布图；
4. 到“通用信号识别”选择真实匹配的任务和文件；
5. 需要批量识别时，使用多文件/目录入口，观察进度和结果卡片；
6. 到“轴承检测”时，先看质量状态，再看诊断结果；
7. 无人机页面当前只能验证输入和图形预览，不能把占位提示当成无人机识别结果；
8. 生成、轻量化和实验页面中的数字必须看清来源和指标定义。

## 14. 当前限制

- 无人机基线和首轮双分支消融已完成训练，但尚未接入软件；
- 当前只有 DroneRF 同源录制级公开数据实验，没有跨来源或真实部署业务准确率证据；
- 第二数据源 VTI_DroneSET 的官方归档、版本、许可和 SHA-256 已核验，但内容受作者密码门保护，尚未完成格式、标签和录制边界审计；
- 历史演示数据不能用于业务指标；
- 部分历史识别路径仍可能在大数据量下占用较多资源；
- HHT 依赖可选安装；
- 正式发布仍需在干净 Windows 环境完成安装、启动、模型、图形和连续运行验收。

## 15. 当前测试情况

最近一次完整回归结果：

```text

```

该数字表示自动化软件测试通过数量，不是模型准确率，也不是无人机识别效果。测试覆盖后台任务、输入读取、质量规则、图形预览、数据来源审计、历史流程和打包路径等内容。

## 16. 下一步建议

1. 保持现有三模型、三随机种子基线冻结，不再根据测试结果修改其配置；
2. 首轮双分支消融和受控加噪压力测试已经完成；噪声增强 TCN 已通过验证集 clean 守门线并改善 0/5 dB，但尚需第二来源或新留出集独立确认；
3. 完成开放集和失败案例实验，并隔离多任务辅助头对类型主任务的负迁移；
4. 按官方要求取得 VTI_DroneSET 密码，完成内容审计后再做跨来源或未知域验证；
5. 冻结可部署模型契约后接入无人机页面；
6. 完成干净机器上的 Windows 安装包验收并整理提交材料。
