> 目的：在不训练模型、不修改界面、不替换历史权重的前提下，调查网上已有的轴承故障诊断代码和模型文件，判断哪些可以作为本项目后续的对照路线。

## 1. 先说结论

本阶段没有找到一个可以直接放进本项目、立即加载并运行的公开轴承故障诊断深度学习权重文件。

目前找到的内容主要分成三类：

1. **代码和流程参考**：有数据切片、时频图转换、CNN/ResNet/Transformer 等实现，但没有随仓库公开可下载的深度学习 checkpoint。
2. **作者报告的结果**：README、CSV、NPY 或图片中有作者自己的实验结果，但这些不是本项目在当前数据和环境下重新得到的结果，不能冒充本项目准确率。
3. **任务方向参考**：例如正常/异常自动编码器或连续小波时频图模型，适合后续研究未知故障、异常预警或时频图路线，但不能直接替代当前四分类对照。

因此，本阶段的合理处理是：**只保留对照记录，不下载外部权重，不接入软件，不改动现有模型。**

## 2. 与本项目当前数据的关系

本项目第一阶段已经在本地建立了独立的 CWRU 数据目录，并下载了 16 个官方 12 kHz `.mat` 文件：

- 正常：4 个；
- 内圈故障 0.007 英寸：4 个；
- 滚珠故障 0.007 英寸：4 个；
- 外圈故障 0.007 英寸、6 点位：4 个。

文件位置为：

```text
datasets/bearing/cwru/raw/
```

这些文件是原始时域振动数据，不是图片，也没有经过切片、归一化或特征转换。网上候选项目多数要求先完成以下某一种处理：

- 从 `.mat` 中读取 `DE_time`；
- 按固定长度（例如 1024 点）切成窗口；
- 或把振动窗口转换成频谱图、连续小波图；
- 再把转换后的数据送入图像分类模型或一维信号模型。

所以，“网上有代码”不等于“可以直接把一个文件拖进本项目就得到预测”。真正接入前还需要核对输入形状、归一化方式、标签顺序、模型结构和权重是否完全匹配。

### 4. 对“网上有没有现成模型”的直白回答

目前调查到的是：**网上有不少轴承故障诊断代码、论文和作者实验结果，但这不等于有可以下载后直接运行的模型权重。** 本次重点检查的公开项目都没有确认到可直接下载并能核验来源的 CNN/Transformer 深度学习 checkpoint。

即使以后找到 `.pth` 文件，也还要继续核对四件事：

1. 文件是不是和公开代码同一版本训练出来的；
2. 输入是不是同一种信号、同一个通道、同一个窗口长度和预处理；
3. 输出数字的标签顺序是否一致；
4. 权重和数据是否允许合法使用。

只要其中一项不一致，模型可能仍然能运行，但输出的类别含义或准确率就不可信。

1. 先选 `CNN-Transformer` 作为“结构复现参考”，单独建立实验目录，不碰现有界面和历史权重；
2. 写一个只读适配器，明确固定 MAT 通道、窗口、标签映射和数据切分；
3. 只在确认代码许可证、数据许可证和权重来源后，才考虑下载外部 checkpoint；
4. 先做单文件、少量窗口的前向兼容性检查，再决定是否做完整对照实验；
5. 所有外部实验结果单独存放并标记来源，不能覆盖当前 baseline 证据。

本阶段到此仍然停在“外部模型调查和兼容性判断”，没有进入训练、界面接入或历史权重替换。
